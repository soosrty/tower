# 塔台 Apple Design 界面审核

日期：2026-09-30。范围：iPhone / Mac 的导航、页面、表单、按钮、图标、信息层级、反馈、动态字号和辅助功能。此轮只审核，未修改产品代码。

## 结论

目前的系统字体、原生表单、统一卡片、按压反馈、节点地图和三步工作流值得保留。最有价值的改进是纠正状态与文案、让操作更容易被发现、提高可读性，以及改善 Mac 的操作效率。没有必要为追求“苹果风格”给所有卡片加玻璃、弹跳或更多装饰。

发现 18 组问题或改进机会：1 项 P1、13 项 P2、4 项 P3。P1 是会误导用户判断配置保护行为的文案错误；P2 是应优先安排的可用性或可访问性问题；P3 是打磨建议。证据和设计判断分开列出，设计建议不等于已复现的功能缺陷。

## 需要优先处理的发现

### D01 · P1 · 兼容性说明承诺“阻止导出”，实际是“跳过并导出”

**已确认，源码对照。** `Tower/Features/Rules/LocalRuleCompatibilityView.swift:44` 仍写着“无法完整保留的拒绝条件会阻止对应客户端导出”。但 `Tower/Services/ConfigurationGenerator.swift:324` 起统计跳过的拦截规则，`:348` 明确输出“这些请求不会被拦截”，并不因这种情况阻止整份导出。

这会让用户在编辑阶段形成错误预期：认为失效的拦截规则一定会阻止导出。导出页又把所有诊断统一收进“兼容性提示”折叠行（`ExportView.swift:1380` 附近），就绪图标仍为绿色。

建议先修正编辑页文案，使其与实际语义一致。设计上可仅在存在拦截失效时常显一条简短摘要，例如“有 2 条拦截规则未生效”，详情继续折叠；不要把全部普通诊断恢复成首页大段警告，也不要改变已经明确的“跳过但不阻止导出”产品策略。

验收：构造一条目标客户端无法表达的 REJECT 条件，核对编辑提示、导出摘要、诊断首条和实际导出结果相互一致。

### D02 · P2 · 品牌蓝同时用于文字与白字按钮底色，对比度不足

**已确认，颜色资源计算；不是深色实机截图结论。** `Tower/Assets.xcassets/AccentColor.colorset/Contents.json` 的明色为 RGB `(0.063, 0.506, 0.980)`，暗色为 `(0.255, 0.658, 1.000)`。按 sRGB 相对亮度公式，白字/蓝底分别约 **3.79:1** 和 **2.54:1**。

`TowerTheme.swift` 的 `PrimaryActionLabel`、`ExportView.swift:1583` 的主导出按钮，以及 `AddSourceSheet.swift:164` / `ImportRuleSchemeSheet.swift:52` 的选中模式都硬编码白色前景。小号 caption 白字在明色下也低于常用 4.5:1 目标；暗色配色甚至低于大字常用 3:1 目标。

建议拆分“链接/强调色”和“白字按钮背景色”，后者使用更深的蓝；不要整体加深暗色 AccentColor 导致链接又看不清。需要同时测正常、按下、禁用、明暗和增强对比度状态。

### D03 · P2 · 已过期订阅仍显示“0 天到期”

**已确认，Mac 界面与源码。** `SubscriptionsView.swift:637` 的 `SubscriptionCardMetrics` 使用 `max(days, 0)`；`:927` 始终显示“X 天到期”。因此今天到期和已经过期都合并为 0。

建议区分“今天到期”“已到期”或“已过期 X 天”，必要时在详情显示具体日期；不要把过期订阅自动停用。用昨天、今天、明天及跨时区样本检查。

### D04 · P2 · Mac 提供不可用的扫码入口，却让用户检查权限

**已确认，平台分支。** `AddSourceSheet.swift:168` 遍历所有录入方式，包含扫码；`QRCodeScannerSheet.swift:23` 的 Mac Catalyst 分支只返回不可用界面，说明却是“请检查相机权限”。更改权限不会让这一实现获得扫码能力。

建议 Mac 隐藏相机扫码入口，或明确显示“Mac 暂不支持相机扫码”，提供粘贴链接/从图片识别等真实可用替代方式。iPhone 端也应区分设备不支持、权限拒绝、暂时不可用，避免所有失败都指向设置。

### D05 · P2 · 预览中已打码，但“复制”会取得未打码凭据，界面没有说清楚

**已确认，源码。** `ExportView.swift:1460` 的配置预览使用 `maskingTailnetAuthKeys`，`:1494` 的复制却写入原始 `configuration.content`。复制完整配置供客户端使用是合理行为，问题在于用户会把屏幕上的打码理解为复制也已脱敏。

建议在预览中明确“预览已隐藏 Auth Key；复制完整配置会包含凭据”，或提供“复制完整配置”和“复制脱敏文本”两个清楚命名的动作。保持完整复制可用，不必每次加确认弹窗。

### D06 · P2 · 添加表单的隐私承诺与已开启的 iCloud 状态冲突

**已确认，文案对照。** `AddSourceSheet.swift:104` 无条件写“订阅内容、节点凭据和转换结果都只保存在这台设备上”，同一文件 WireGuard 分区已正确说明私钥会进入用户主动开启的 iCloud 同步；设置也支持同步订阅和凭据。

建议统一表述为“解析与转换在本机完成；仅在您开启 iCloud 同步后同步订阅与节点”。“在哪里处理”和“保存到哪里”应分别表达，避免绝对化的“只在本机”。

### D07 · P2 · 导出页两个主要操作看起来像只读信息

**已确认，Mac / iPhone 截图和源码。** `ExportView.swift:104,111` 对“规则方案”和“协议筛选”显式设置 `showsChevron: false`，并用 `.buttonStyle(.plain)`；实际分别跳到规则页和打开筛选。相邻“高级选项”和“配置预览”却有箭头。

建议恢复清晰的可操作信号：规则用“更换”或外跳含义明确的按钮，协议筛选用 disclosure 箭头；统一按下反馈。不要把只读统计、跨标签页导航和就地展开画成同一种行。

### D08 · P2 · 全局设置藏在“导出”页，设置内容又集中在一张长卡片

**现状已确认，改善方向属于信息架构建议。** `ExportView.swift:201` 才提供设置入口；设置同时包含订阅提醒、自动刷新、节点处理、导出、Tailscale、iCloud 和重置。`SettingsView.swift:339` 将许多职责放入“节点与配置”卡片。

建议 iPhone 给全局设置一个各主页面一致可达的入口；Mac 提供标准设置命令。设置分成“订阅与提醒”“节点与导出”“同步与数据”等小组。导出高级选项中的重复开关可保留作快捷入口，但要让用户知道它是全局偏好。

### D09 · P2 · 规则卡片的“编辑、选用、展开”层级不够明确

**实际界面观察，属于可用性改善建议。** `RulesView.swift:373` 的大面积主体打开编辑，右侧圆圈负责选用，下方再展开策略组。页面还需要常驻“点击规则方案即可修改规则”来解释动作。

建议保留三种能力，但给选用明确的“使用此方案 / 当前使用”表达，把编辑作为清楚命名的次级动作。选用成功时让当前方案摘要同步反馈。不要让点击整张卡片同时切换方案并进入编辑；现有“编辑未选中方案不影响导出”的提示应保留。

### D10 · P2 · “显示策略组 Emoji”是开关，却没有表达状态

**已确认，Mac 菜单与源码。** `RulesView.swift:743` 始终显示相同标题，`:871` 实际取当前值的反值。已经显示 Emoji 时点击“显示”反而隐藏，菜单也没有勾选状态。

建议使用绑定状态的 Toggle，或根据状态显示“隐藏策略组 Emoji / 显示策略组 Emoji”。菜单标题“编辑”也可以改为“方案选项”，因为其中包含 DNS、显示偏好、另存和恢复。

### D11 · P2 · 若干辅助功能元素缺少上下文，装饰图标进入朗读

**Mac 辅助功能树和源码已确认；尚未进行实体 VoiceOver 听读。**

- `RulesView.swift:1132` 的多个策略路由按钮只暴露“节点选择”等重复值，缺少所属组。应朗读“Netflix，当前策略：节点选择，修改策略”。
- `RulesOverviewCard` 的装饰图标在实际树中暴露为“连拍快照”，DNS 行装饰图标暴露为“地球仪键”。应对装饰图标设 `accessibilityHidden(true)`，保留有意义的组合标签。
- Tailscale 空 Auth Key 的图标式粘贴按钮在 Mac 树中无名称（`TailnetSettingsView.swift:334`）；应显式命名“粘贴 Auth Key”。
- `NodeCountryPicker.swift` 的“自动识别”没有像具体国家那样显示当前选中状态，应补视觉勾选与 selected 语义。

验收应使用 VoiceOver 按钮转子逐项检查，同名重复项能单独听懂，不依赖旁边文本的位置。

### D12 · P2 · 大字号支持不均匀，局部仍用固定小字与强制单行缩放

**源码已确认；是否裁切须分页面实测。** 地图图例 `NodeMapOverview.swift:269` 和国家标签 `WorldDotMapView.swift:584` 使用固定 **10 pt**。订阅配额与状态行（`SubscriptionsView.swift:849,911`）以及分享三列按钮（`SharePayloadSheet.swift:130`）采用单行加缩小字体。

建议图例使用动态 caption，并允许换行；地图标签采用有上限的字号增长，同时提供可读的地区列表替代路径。订阅状态在窄屏/辅助字号下改成两行，错误信息不要挤在日期、节点数、刷新与分享之间。分享动作可按可用宽度转为纵向列表。

本轮最大辅助字号的客户端筛选测试通过，截图中长品牌名换行、移除与拖动控件仍可操作。不要将这个结果推广为全 App 大字号通过，也不要把该页面必要的换行当成需要缩小字体的理由。

### D13 · P2 · 长表单的错误定位与禁用原因仍需完善

**源码证据，具体键盘遮挡未实测。** Tailscale 在点击保存后才验证，将 `errorMessage` 放在表单靠后位置（`TailnetSettingsView.swift:237,278`）。添加节点也统一在所有参数之后放错误信息（`AddSourceSheet.swift:92`）。名称/Emoji 编辑器会禁用保存，但对非法 Emoji 缺少就近解释（`RulesView.swift:1847` 附近）。

建议字段失焦时做轻量校验，保存失败时滚动并聚焦第一处错误，把原因放在对应字段下。复杂协议的必填项优先显示，冷门参数放高级分区；保留当前值与草稿，避免因切页丢失输入。

### D14 · P2 · Mac 的大屏、键盘与菜单能力仍未充分利用

**Mac 界面和源码已确认，具体布局方案需要原型验证。** 当前根界面仍是三页 `TabView`（`TowerApp.swift:97`）；主页面用最大宽度限制适配，但大量内容仍是单列卡片、底部导出条和多层 modal。源码未找到产品动作的 `keyboardShortcut`、`UIKeyCommand`、`UIMenuBuilder` 或 `.commands` 实现；系统自带编辑快捷键不在这个结论内。

建议先补高收益动作：新增来源、刷新、搜索、导出、设置的菜单命令和快捷键。再为宽窗口验证“来源/方案列表 + 详情”的分栏原型，减少同一任务多次打开 sheet。窄窗口保留紧凑布局，不必直接推翻所有现有界面。

### D15 · P3 · 恢复备份页缺少独立的加载状态

**源码已确认。** `SettingsView.swift:1122` 在列表为空时直接显示“暂无同步备份”，随后异步加载，但视图没有独立的读取中/读取失败状态。加载期间的空集合不能证明没有备份。

建议区分“正在读取”“没有备份”“读取失败，重试”，恢复时显示所选快照日期及忙碌状态，完成后给清楚结果。此轮未执行真实 iCloud 恢复。

### D16 · P3 · 图标资源的光学尺寸和外壳处理可以统一

**资源观察和部分实际界面。** 20 个客户端图标混合了无底标志、白底方图、已经带圆角/阴影的完整 App 图标，统一再经 `ClientAppIcon` 裁切、描边、阴影（`ExportView.swift:1206`）后，部分显得有双层外壳，标志视觉重量也不一致。

建议保持官方品牌图像，规范各资产的内边距和光学尺寸，避免给已经带外壳的图标再叠明显阴影。用 27 / 40 / 58 pt 和明暗背景做接触表复核，不要把所有品牌强行重画成同一种风格。

塔台主图标的轮廓和蓝色玻璃已有辨识度，可保留。暗色源图的顶部天线和底座与背景较接近，可在小尺寸下适当提亮边缘；这是视觉打磨建议，不是已确认的上架问题。

### D17 · P3 · 少量反馈和动效还可更一致

**源码已确认，手感属于待验证项。** `SharePayloadSheet.swift:50` 第一次复制后 `copied` 一直为 true，后续点击没有新的状态变化或成功触感触发。`WelcomeView.swift:169` 使用带 bounce 的翻页动画，即使由按钮触发；其他高频界面已统一为克制的 `TowerMotion`。

建议复制反馈短暂显示后恢复，连续点击也有即时按压反馈；按钮翻页可用不回弹的过渡，保留手势翻页的自然跟随。不要给所有点击加触感，也不要因为理论参数就重写已经调好的地图惯性。

### D18 · P3 · 小图标控件可以统一放宽触摸命中区

**代码尺寸已确认，实际有效命中范围仍需触摸/AX frame 验证。** 地图复位为 38×38（`WorldDotMapView.swift:495`），Auth Key 眼睛按钮为 28×28（`TailnetSettingsView.swift:347`），关键词删除为 28×44（`NodeNameFilterEditor.swift:230`）。它们比 App 中普遍采用的 44×44 区域更紧。

建议保留图标视觉尺寸，扩大透明命中区域，特别是靠近输入框的眼睛/删除按钮。这里采用 44×44 作为触摸舒适目标，不把小于 44 的所有控件都判为违反平台最低要求；也不能靠扩大区域制造相邻按钮重叠。

## 设计依据

- 用户指定的 [apple-design 技能](/Users/jzb/.agents/skills/apple-design/SKILL.md)：即时反馈、可中断运动、明确状态、动态字号、克制的信息层级。技能中的网页实现方法按原生 SwiftUI 的能力转译，不机械移植 CSS 或 Web 动画库。
